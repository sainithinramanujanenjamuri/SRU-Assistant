# Implementation Plan — Phase 9: RAG Evaluation

Turn SRU Assistant into a measurable, empirically evaluated research framework by implementing a quantitative evaluation framework for retrieval, generation, citation, and latency across the 10 canonical academic query categories.

> [!IMPORTANT]

## 3. Detailed Component Specifications

### A. Data Models (`evaluation/models.py`)
- `BenchmarkQuery`:
  - `query_id: str`: unique identifier (e.g. `q01_direct_factual_course_code`)
  - `query: str`: natural-language student question
  - `category: str`: one of the 10 canonical categories (`direct_factual`, `date_based`, `course_related`, `regulation`, `department_specific`, `multi_document`, `paraphrased`, `ambiguous`, `out_of_knowledge_base`, `version_sensitive`)
  - `expected_answer: str`: gold-standard answer or standardized fallback
  - `expected_chunk_ids: list[str]`: ground-truth chunk IDs
  - `expected_document_names: list[str]`: supporting document names
  - `expected_pages: list[int | None]`: supporting page numbers
  - `expected_entities: list[str]`: required key entities
  - `expected_behavior: str`: `"answer"` or `"insufficient_evidence"`
  - `is_answerable: bool`: boolean flag distinguishing answerable vs out-of-knowledge-base queries
  - `description: str`: query design rationale
- `RetrievalMetrics`:
  - `recall_at_k: dict[int, float]` (K=1, 3, 5)
  - `precision_at_k: dict[int, float]` (K=1, 3, 5)
  - `mrr: float`
  - `ndcg_at_k: dict[int, float]` (K=3, 5)
  - `latency_ms: dict[str, float]` (mean, median, p95)
- `GenerationMetrics`:
  - `groundedness: float` (factual claims supported by retrieved context)
  - `answer_relevance: float` (query-answer semantic and intent alignment)
  - `context_relevance: float` (proportion of retrieved chunks that are relevant)
  - `correctness: float` (token overlap / entity containment against gold standard)
  - `completeness: float` (coverage of key expected entities)
  - `unsupported_claim_rate: float` ($1.0 - \text{groundedness}$)
- `CitationMetrics`:
  - `citation_precision: float` (verified citations / total citations)
  - `citation_recall: float` (supported claims cited / total factual claims)
  - `citation_completeness: float` (ratio of factual claims with valid citations)
  - `evidence_support: float` (mean support score across citations)
- `QueryEvaluationResult`: Single query evaluation capturing metrics and pipeline outputs.
- `ExperimentRunResult`: Aggregate metrics, latency distributions, and category breakdowns for a specific RAG configuration.
- `EvaluationReport`: Multi-experiment comparative report.

### B. Benchmark Dataset (`evaluation/datasets/` & `data/benchmarks/eval_benchmark_suite.json`)
A curated dataset spanning all 10 canonical categories specified in `roadmap.md` (lines 740–752) and `agent.md` (lines 503–514):
1. `direct_factual`: Direct course codes and syllabus titles.
2. `date_based`: Examination and classwork schedule dates.
3. `course_related`: Topics, objectives, and course descriptions.
4. `regulation`: Academic regulations (R23).
5. `department_specific`: Computer Science & Engineering VII semester queries.
6. `multi_document`: Cross-document synthesis (Course details + Examination schedule).
7. `paraphrased`: Semantic variations of academic queries without literal keywords.
8. `ambiguous`: Under-specified academic queries requiring broad retrieval.
9. `out_of_knowledge_base`: Unindexed domain queries (transport, fees, external facts) testing zero-hallucination safe refusal.
10. `version_sensitive`: Queries specifying academic year `2026-27`.

### C. Retrieval Evaluation Engine (`evaluation/retrieval/metrics.py` & `evaluator.py`)
- **Recall@K**: $\frac{|\text{Retrieved}_K \cap \text{Relevant}|}{|\text{Relevant}|}$
- **Precision@K**: $\frac{|\text{Retrieved}_K \cap \text{Relevant}|}{K}$
- **MRR (Mean Reciprocal Rank)**: $\frac{1}{\text{rank}_1}$ (first relevant chunk)
- **nDCG@K (Normalized Discounted Cumulative Gain)**:
  $$\text{DCG@K} = \sum_{i=1}^K \frac{rel_i}{\log_2(i + 1)}, \quad \text{nDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}$$

### D. Generation Evaluation Engine (`evaluation/generation/metrics.py` & `evaluator.py`)
- **RAG Triad Implementation**:
  1. **Groundedness (Faithfulness)**: Ratio of generated factual claims supported by the retrieved context chunks (using `ClaimExtractor` and `CitationVerifier`).
  2. **Answer Relevance**: Substantive token overlap and entity alignment between the query and generated answer (or correct standardized refusal on unanswerable queries).
  3. **Context Relevance**: Ratio of retrieved context chunks that contain ground-truth relevant evidence.
- **Factual Correctness**: Token F1 score and key entity overlap with expected answer.
- **Completeness**: Proportion of gold-standard entities present in the generated answer.
- **Unsupported Claim Rate**: $\frac{\text{Unsupported Factual Claims}}{\text{Total Factual Claims}}$.

### E. Comparative Experiments Runner (`evaluation/evaluator.py`)
Implements the 4 comparative experiments from `roadmap.md` Section 36 & 37:
- **Experiment A — Vector RAG**:
  - Dense retriever only (`VectorRetriever`)
  - No re-ranking, basic context builder
  - Baseline generator without grounding validation
- **Experiment B — Hybrid RAG**:
  - Dense + Lexical retrieval (`HybridRetriever` with RRF fusion)
  - No re-ranking, basic context builder
  - Baseline generator without grounding validation
- **Experiment C — Hybrid + Re-ranking**:
  - Hybrid retrieval + `DeterministicCrossFeatureReranker` (`EnhancedRetriever`)
  - Token-budgeted context builder with relevance threshold
  - Baseline generator without grounding validation
- **Experiment D — Full Grounded Pipeline**:
  - `EnhancedRetriever` (Hybrid + Filtering + Re-ranking)
  - `ConflictDetector` + `GroundingValidator` (Phase 7)
  - `ClaimExtractor` + `CitationMapper` + `CitationVerifier` + `CitationFormatter` (Phase 8)

### F. CLI Evaluation Harness & Reporting (`scripts/evaluate_rag.py` & `evaluation/reports/`)
- CLI command: `python scripts/evaluate_rag.py` with flags:
  - `--experiments`: `all`, `A`, `B`, `C`, `D`
  - `--dataset`: path to benchmark JSON
  - `--output`: path to output results JSON
  - `--markdown`: export markdown report
  - `--category`: filter to specific category
  - `--runs`: repetitions per query for latency measurement
- Formatted output tables:
  1. Executive Comparative Summary Table
  2. Detailed Retrieval Metrics Table (Recall@1, 3, 5, Precision@1, 5, MRR, nDCG@5)
  3. Generation & RAG Triad Table (Groundedness, Answer Relevance, Context Relevance, Correctness)
  4. Citation Metrics Table (Citation Precision, Citation Recall, Citation Completeness)
  5. Multi-Stage Latency Breakdown Table (Retrieval, Rerank, Gen, Grounding, Citation, Total)
  6. Academic Category Breakdown Table
